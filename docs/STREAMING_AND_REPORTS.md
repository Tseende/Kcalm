# Постепенные ответы и компактный отчёт недели

## Отчёт

Недельный отчёт показывает график, средние показатели, главный совет и короткие наблюдения.
Таблица семи дней находится в `Doc.expandable("📋 Показать по дням", ...)`: это HTML
`<blockquote expandable>` с вложенной таблицей, поддержанный в Bot API 10.5.
Старый раздел «Подробности» остаётся отдельным. Если rich-сообщение отклонено, обычный
вариант показывает все строки и таблицу моноширинным текстом — данные не исчезают.

Документация: https://core.telegram.org/bots/api#inputrichblockexpandableblockquotation

## Ответ ИИ

`CHAT_STREAMING=true` включает поток для интерактивной поддержки и вопросов по отчётам.
Mini App и фоновые уведомления используют прежний запрос. Выключатель возвращает обычное
поведение без изменения модели или промптов.

1. Обработчик создаёт отдельный контекст ответа (у каждого ответа свой ненулевой draft_id).
2. OpenRouter получает `stream=true`; SSE собирается в исходный JSON для прежних проверок и
   записи в базу. В UI извлекается только поле `reply`, включая экранированные символы.
   `reasoning`, `summary`, риск и остальные служебные поля не показываются.
3. `sendMessageDraft(text="")` показывает нативное Thinking…; placeholder/превью обновляется
   также при долгой генерации. Черновики отправляются не чаще одного раза в 0,7 секунды.
4. Те же проверки фактов, чисел и формулировок применяются к промежуточному тексту. В Telegram
   появляются законченные фразы, а не обрывки чисел и слов. Полный ответ по-прежнему проходит
   окончательную проверку сервисом поддержки или ассистентом.
5. Когда ответ готов, worker черновика останавливается. Вызывается именно `sendMessage`:
   этот финальный вызов не превращается middleware в `sendRichMessage`. В истории остаётся
   одно обычное сообщение. Служебный статус голосового при необходимости удаляется.

Это настоящий поток от модели, без искусственной анимации уже полученного текста. Если
ответ готов быстро, он может появиться целиком раньше следующего обновления черновика.

При отказе Telegram от draft используется обычная отправка. При HTTP 400/422 на SSE
к провайдеру выполняется обычный JSON-запрос. Обрыв сети получает штатный повтор с очищенным
превью. Ошибка генерации приводит к обычному запасному ответу. Счётчики стоимости и токенов
учитывают итоговый usage потока, а не складывают одинаковые накопительные снимки.

Worker закрывается при завершении или отмене обработчика; законченный контекст не включает
стриминг в фоновых задачах. Кнопка остановки генерации пока не включена (`can_stop=false`).

Документация: https://core.telegram.org/bots/api#sendmessagedraft
и https://openrouter.ai/docs/api_reference/streaming

Проверки: `python -m pytest -q tests/test_streaming.py tests/test_rich.py tests/test_reports.py`.
