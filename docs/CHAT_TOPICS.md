# Дневник и Поддержка в Telegram

При `CHAT_TOPICS_ENABLED=true` (по умолчанию) бот при запуске вызывает
[`setMySettings`](https://core.telegram.org/bots/api#setmysettings): включает темы и боковую
панель, запрещает пользователю создавать дополнительные темы и сохраняет
`callback_query_mode=default`, чтобы кнопки продолжали получать `CallbackQuery.message`.
Используется небольшой адаптер метода API 10.5, поскольку установленный aiogram его ещё не содержит.

Для пользователя с настроенным профилем темы создаются при следующем сообщении, нажатии кнопки
или отправке уведомления. После завершения онбординга они создаются автоматически. В каждой
новой теме появляется короткое описание. Идентификаторы сохраняются в таблице `chat_topics`;
перезапуск не создаёт дубликаты. Существующие сообщения остаются на своих местах.

- **📒 Дневник**: еда текстом, голосом и по фото; вода, вес, сон, активность;
  подтверждения записей, карточки дня, обычные напоминания и отчёты.
- **💬 Поддержка**: разговор о самочувствии, привычках и тяге к еде, виджет паузы
  и последующий вопрос о состоянии. Простое упоминание съеденной еды здесь не считается записью.
  Явная просьба «запиши банан 100 г» или «запиши 250 мл воды» записывает данные и подтверждает их
  в этой же теме. Фото еды также можно прислать здесь. Карточка дня обновляется в Дневнике.

`/talk`, `/craving` и распознанная тяга к еде направляют ответ в Поддержку, даже если запрос пришёл
из Дневника. Открытый разговор в Поддержке не перехватывает обычные записи в Дневнике.
Обычные ответы остаются в теме исходного сообщения. Сообщения из основного чата без темы
обрабатываются как Дневник. Отправки планировщика по умолчанию идут в Дневник;
продолжения поддержки явно выбирают Поддержку.

FSM использует `USER_IN_TOPIC`. Ожидания ввода, окна подписей к фото и короткая память
ассистента разделены по темам. Данные дневника и профиль остаются общими для пользователя.
Изменение существующего сообщения всегда относится к исходному сообщению и не переносит его.

Если тема закрыта, при отправке бот открывает её снова. Если Telegram сообщает, что тема удалена,
бот создаёт замену и повторяет отправку. При частичном сбое создания уже созданная тема сохраняется;
повтор не чаще раза в минуту. При недоступном `setMySettings` бот пишет предупреждение в журнал
и продолжает работу без автоматических тем; для повторной настройки нужен перезапуск.

## Запуск и отключение

Миграция `039_chat_topics.sql` применяется штатным запуском `python -m app.bot`.
Для проверки запустить бота и написать `/start` с уже настроенным профилем, затем проверить:

1. В боковой панели появились Дневник и Поддержка.
2. В Дневнике «выпил 250 мл воды» создаёт запись.
3. В Поддержке обычная реплика продолжает разговор, а «запиши 250 мл воды» создаёт запись там же.
4. `/talk` из Дневника отправляет ответ в Поддержку.
5. Напоминания, новая карточка дня и виджет паузы попадают в соответствующие темы.

`CHAT_TOPICS_ENABLED=false` отключает автоматическое создание и маршрутизацию тем в приложении.
Уже созданные темы и настройка Telegram сохраняются: бот их не удаляет. Поведение записей
возвращается к `CHAT_LOGS_FOOD` (по умолчанию выключено). Полное выключение режима тем в Telegram
выполняется отдельно через настройки бота.

Офлайн-проверки: `python -m pytest -q tests/test_topics.py`.
