# Готовая база продуктов (БЖУ на 100 г) — 17 ноября 2026

Базовая таблица готовых/основных продуктов для бота: 120 позиций, которые люди реально
записывают в дневник — варёное, тушёное, жареное, запечённое, каши, гарниры, молочка,
базовые овощи, хлеб.

## Файлы

| Файл | Что внутри |
|---|---|
| `products_ready.csv` | 120 строк в формате импорта бота: `name_ru,name_en,kcal_100g,protein_100g,fat_100g,carbs_100g,source,external_id` (`source=seed`, `external_id=ready:*`) |
| `products_ready_full.csv` | то же + раздел, источник, ссылка на источник, значение второго источника, вердикт сверки, примечание (UTF-8 BOM — открывается в Excel) |
| `products_ready.xlsx` | 3 листа: «БЖУ», «Проверка» (по каждой позиции второй источник и Δ%), «Методика» |
| `seed_ready_foods.sql` | обновляет общие seed-записи с теми же названиями и вставляет новые |

## Источники

* **USDA FoodData Central** — SR Legacy (2019) + Foundation Foods (2024), локальные дампы.
  Основной источник для однокомпонентных продуктов; в описании записи зафиксирован способ
  приготовления (stewed / roasted / fried / braised / dry heat).
* **health-diet.ru** — таблицы Института питания (Скурихин, Тутельян) и рецептурные расчёты.
  Источник для русских блюд: каши, тушёная капуста, пюре, жареные овощи, сырники, плавленый сыр.
* **calorizator.ru** — второй русский справочник: молочка по % жирности, хлеб, консервы,
  национальные блюда. Полный каталог спарсен (6 765 позиций) и использован как кросс-чек.
* **foodstruct.com** — только картофель фри (готовый продукт): в USDA нет готового аналога на 100 г.

## Как выбиралось значение

1. Однокомпонентные продукты (мясо, рыба, овощи, крупы, яйца) — USDA, значение для того же
   способа приготовления, что в названии.
2. Русские блюда и молочка по % жирности (творог 5%, сметана 20%, каши, котлеты, тушёная
   капуста, сырники) — русские таблицы: у них правильная база «как на упаковке/как в столовой».
3. Каждая строка сверена со вторым источником: 74 из 120 позиций имеют второе значение
   (33 совпадают в пределах ±10%, 25 — 10–25%, 16 — сильное расхождение, разобраны ниже).
4. Контроль арифметики: ккал ≈ 4×Б + 9×Ж + 4×У. Строк с Δ>12% нет — все значения согласованы.

## Известные ограничения

* **Жарка** — значения предполагают 5–10 г масла на 100 г готового продукта (как в Скурихине).
  При жарке без масла берите вариант «запечённый/варёный».
* **Крупы** — зависят от количества воды. Гречка/пшено — Скурихин (рассыпчатая/вязкая),
  рис/булгур/кускус/киноа/перловка — USDA.
* **Сырое vs готовое** — в таблице есть и сырые, и готовые версии (грудка, рис, гречка,
  макароны). Бот должен спрашивать, взвешивал ли пользователь до или после готовки.
* **Сильные расхождения (16 строк)** — оставлено значение основного источника, второе видно
  в колонке проверки: телятина (203 vs 131), свинина запечённая (231 vs 160), баранина
  (268 vs 344), печень говяжья (191 vs 117), треска (105 vs 77), скумбрия (262 vs 191),
  форель (168 vs 119), индейка сырая (114 vs 84), творог обезжиренный (110 vs 72),
  капуста тушёная (75 vs 102), мидии (89 vs 172), морковь/помидор/огурец/тыква/цветная
  капуста — разные сорта и способы, расхождение в пределах 30–60%.
* **Бренды** — у брендов БЖУ отличается на 20–30% (творог, сосиски, хлеб): для брендовых
  продуктов нужна этикетка, а не эта таблица.

## Как загрузить

При запуске бота каталог загружается миграцией `035_ready_foods.sql`.

```bash
# проверка импорта на отдельной копии SQLite
sqlite3 /path/to/catalog-copy.db < docs/food-database-audit/seed_ready_foods.sql
```

Скрипт обновляет общие записи с тем же русским названием на месте, сохраняя их ID
и привязки в дневнике. Для новых названий используются ID вида `ready:…`.
На проверенной копии справочника из 355 позиций добавились 35 названий и изменились
81 существующая запись. После импорта 390 активных общих продуктов без дублей
по русскому названию. Повторный запуск не меняет справочник.
