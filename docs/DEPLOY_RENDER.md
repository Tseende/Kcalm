# Деплой: Render (бесплатно) + Turso (БД)

Как это устроено: бот и Mini App работают в одном процессе на Render, данные лежат в Turso (облачный SQLite),
Telegram шлёт сообщения боту по webhook. Диск Render временный: после рестарта локальный файл БД
пересобирается из Turso, фото восстанавливаются из таблицы `photo_blobs`.

## 1. Turso
1. Зарегистрируйся на turso.tech, создай базу (регион в Европе, например Frankfurt) и скопируй:
   - URL вида `libsql://<база>-<организация>.turso.io` → `TURSO_DATABASE_URL`
   - токен доступа (Create token, без срока или длинный) → `TURSO_AUTH_TOKEN`
2. Опционально перенеси текущие данные (локальный `data/health.db` и фото). Впиши обе переменные в локальный `.env` и запусти:
   ```bash
   .venv/bin/python -m app.dbimport data/health.db
   ```
   Скрипт остановится, если в облаке уже есть пользователи. Он ничего не удаляет и не трогает локальный файл.
   Если данные не нужны, пропусти шаг: схема создастся сама при первом запуске.

## 2. GitHub
Render разворачивает код из git. Папка `bot/` лежит вне git: создай отдельный репозиторий из её содержимого
(`.env`, `data/` и `.venv/` уже в `.gitignore`, секреты в репозиторий не попадут). Репозиторий лучше сделать приватным.

## 3. Render
1. New → Blueprint → выбери репозиторий. Render прочитает `render.yaml`.
2. Введи секреты: `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `TELEGRAM_BOT_TOKEN`, `OPENROUTER_API_KEY`, `ALLOWED_TG_IDS`.
3. После первого деплоя возьми адрес сервиса (`https://<имя>.onrender.com`) и добавь:
   - `WEBHOOK_BASE_URL` = этот адрес без слэша в конце
   - `WEBAPP_URL` = этот адрес + `/app/`
   Сервис перезапустится, поставит webhook и кнопку «Приложение» в меню бота.
4. Проверка: `https://<имя>.onrender.com/healthz` отвечает `{"ok": true}`; в логах Render строки «БД готова (Turso)» и «режим webhook».

## 4. Не давать сервису засыпать
Бесплатный сервис засыпает через 15 минут без запросов, и тогда не сработают напоминания по расписанию
(15-минутный чек-ин, утренняя сводка). Сообщения в Telegram его разбудят, но не сразу (холодный старт около минуты).
Заведи бесплатный пинг (UptimeRobot или cron-job.org): GET `https://<имя>.onrender.com/healthz` каждые 5 минут.
Бесплатных 750 часов в месяц хватает на один сервис, работающий круглосуточно.

## Ограничения
- Бэкапы по расписанию в облачном режиме выключены: данные уже в Turso. Свою копию делай через панель или CLI Turso.
- Фото хранятся в базе (`photo_blobs`) и скачиваются при каждом старте. Для личного дневника это нормально,
  но при тысячах фото старт замедлится.
- Лимиты бесплатных тарифов Render и Turso меняются, сверься с их страницами цен.
- Связь с настоящим Turso в этой сессии не проверялась (учётных данных не было). Логика работы с БД прогнана
  на локальном libSQL (713 тестов проходят; те же тесты на обёртке libSQL: 700 из 705, остальные пять проверяют `PRAGMA user_version` и локальный бэкап); первый запуск на Turso стоит
  сначала проверить по логам.
